# MAO CORE — Voice-Operated Portfolio

**オレンジ色の発光コアに話しかけて、プロフィール・研究・業績などを開く個人ホームページ。**

このREADMEは、実装担当者・Claude Code・Codexに渡すための**実装仕様書**です。完成済みのアプリや検証済みのリポジトリを説明するものではありません。以下の仕様に沿って実装し、末尾の受け入れ条件を確認してください。

- オーナー表示名：Mao Takubo / 田窪真大
- 公開先候補：<https://mao-takubo.github.io/>
- 初期言語：日本語
- 公開方式：GitHub Pages
- 基本構成：Vite + TypeScript + Three.js + HTML/CSS
- 運用方針：有料API・独自バックエンド・有料素材を使わない
- 本書の作成日：2026-11-14（日本時間）

> 最優先の体験は「コアが自分の声で案内し、訪問者がSPEAKを押して『ステータス』と話すと、ゲーム風のステータス画面が展開すること」です。見た目だけのデモで終わらせず、音声とクリックの両方で全メニューへ移動できるようにします。

## 1. 完成イメージ

初回表示では、黒い空間の中央に、オレンジから金色に光る立体的なコアが浮かびます。中心球、回転リング、ワイヤーフレーム、粒子で奥行きを作ります。

訪問者がコアまたは「起動」をクリックすると、オーナーが録音した声で「何をする？」と案内します。訪問者がSPEAKボタンを押して「ステータス」と話すと、コアが「ステータスを表示する」と応答し、コアの隣にSF風のプロフィールパネルが展開します。

「研究」「業績」「プロジェクト」「連絡先」「ヘルプ」「戻る」なども同じ操作で選べます。各項目はクリック・タップ・キーボードでも選択できます。

### 参考画像の読み取り

| 参考 | 取り入れる要素 |
| --- | --- |
| 添付1：青いJARVIS風画面 | 角を切ったパネル、細い発光枠、グリッド、階層のある文字、ステータス表示、展開アニメーション |
| 添付2：オレンジ色の球体 | 明るい中心、立体的な回転リング、線の球殻、散る粒子、金色の光 |

配色は**黒＋オレンジ／金色**に統一します。添付1の青色よりも、添付2のコアと調和する色を優先します。参考画像のロゴ・文字・素材をそのまま流用せず、形と動きから独自に構成します。

参考画像を別途受け取れない実装環境でも、本書だけで作業を進められるようにします。画像がなくても実装を止めないでください。

## 2. 必須仕様と初期版の範囲

### 必須

- 手続き的に生成する3D発光コア。
- オーナーの録音音声を再生できる仕組み。
- 再生音声とコアの発光・動きの同期。
- SPEAKボタンによる日本語の音声認識。
- 登録語と表示画面を対応させるコマンド処理。
- 複数のメニュー、画面を閉じる操作、ヘルプ。
- ステータス・研究・業績・プロジェクト・連絡先のパネル。
- 音声を使わずに全内容を閲覧する操作。
- 音声・3Dが利用できない場合の代替表示。
- デスクトップ・モバイルへの対応。
- 本番用ビルドとGitHub Pagesへの公開手順。

### 初期版に含めないもの

- LLMによる自由会話。
- 声のクローン作成・音声モデルの学習。
- 常時マイク監視やウェイクワード。
- ログイン、データベース、独自の音声認識サーバー。
- 課金API、利用者のAPIキー入力、有料アセット。
- 手の認識、カメラ、不要なOS操作権限。
- サイト閲覧者への無断録音・認識履歴の保存。

機能を追加する際も、まず本書の必須体験を完成させます。

## 3. 利用フロー

1. **アクセス**
   - コアを表示する。
   - 「クリックして起動」「音声なしで見る」を表示する。
   - マイク・音声再生を自動で開始しない。
2. **起動**
   - 起動クリック内で必要なAudioContextを開始または再開する。
   - 「何をする？」を再生し、字幕も表示する。
   - 選べるメニューとSPEAKボタンを表示する。
3. **入力**
   - SPEAKを押すと認識を開始する。初回はブラウザがマイク許可を求める場合がある。
   - 「LISTENING／聞いています」を表示する。
   - 確定前の認識文字は補助表示に留める。
4. **選択**
   - 確定した発話を正規化し、コマンドを1つ決める。
   - マイクの認識を終了する。
   - 該当の音声とパネル表示を開始する。
5. **閲覧**
   - PCではコアを左へ移動して縮小し、右にパネルを展開する。
   - モバイルではコアの下にパネルを展開する。
6. **次の操作**
   - パネル表示中もメニューとSPEAKを使える。
   - 別の項目を選ぶと表示を切り替える。
   - 「戻る」、閉じるボタン、Escapeでパネルを閉じる。

ブラウザが音声再生を止めた場合は、閲覧を維持したまま「音声を再生」ボタンを出します。

## 4. メニューと発話の対応

| ID | 表示名 | 認識する発話の例 | コアの返答 | 表示内容 |
| --- | --- | --- | --- | --- |
| status | STATUS / ステータス | ステータス、プロフィール、自己紹介、ステータスを見せて | ステータスを表示する | 名前、所属、研究分野、公開リンク |
| research | RESEARCH / 研究 | 研究、研究内容、研究を見せて | 研究内容を表示する | 研究テーマ、概要、関連資料 |
| publications | PUBLICATIONS / 業績 | 業績、論文、発表、論文一覧 | 業績を表示する | 論文・発表・共著情報とリンク |
| projects | PROJECTS / プロジェクト | プロジェクト、作品、制作物、コード | プロジェクトを表示する | 制作物、説明、リポジトリ |
| contact | CONTACT / 連絡先 | 連絡先、コンタクト、メール | 連絡先を表示する | 公開メール・GitHub等 |
| help | HELP / ヘルプ | ヘルプ、使い方、何ができる、選択肢 | 選べる項目を表示する | 操作方法とメニュー一覧 |
| back | BACK / 戻る | 戻る、閉じる、ホーム、最初に戻る | ホームに戻る | 表示中パネルを閉じる |

発話は厳密な一語一致だけにしません。「プロフィールを見せて」も選べるようにします。ただし、単純な部分一致で最初に見つかった項目を即実行しないでください。

### マッチング方針

1. Unicode NFKCで正規化し、英語は小文字にする。
2. 空白と句読点を整理する。
3. 登録した完全一致表現を優先する。
4. 明示した依頼表現を取り除き、別名辞書と照合する。
5. 補助的にキーワード照合し、候補が1つだけなら実行する。
6. 「ステータスと研究」のように複数候補なら選択肢を示す。
7. 不明な発話は勝手に画面を開かず、「もう一度話すか、項目を選んでください」と案内する。

「研究は開かない」のような否定表現は実行しないものとし、登録外の複雑な文は再選択を促します。自由な自然言語理解を保証しません。

「戻る」は画面を閉じる操作に限定し、ブラウザ履歴の移動には使いません。

## 5. 画面デザイン

### ホーム画面

- 背景：ほぼ黒。弱い奥行き表現として微細なグリッドや粒子を加える。
- 中央：発光コア。PCでは視覚的な直径約320〜500px、画面に合わせて調整。
- 上部：小さな「MAO CORE」とオーナー名。
- 下部：字幕、SPEAK、クリック可能なメニュー、ミュート。
- 起動前：コア付近に「クリックして起動」と「音声なしで見る」。
- 画面に大量の説明文や巨大な見出しを置かない。
- 常にマイクの待機／入力中が分かる。

### パネル

- 背景は可読性を確保した濃い半透明色。
- 細いオレンジ色の枠、角の切り欠き、控えめな発光。
- パネルタイトル、本文、閉じるボタンを明確に配置。
- 文字はDOMで描く。Canvasに本文を焼き込まない。
- 長い研究説明や業績一覧はパネル内でスクロールできる。
- 開閉は200〜450ms程度を目安にし、操作を長く待たせない。
- パネルが開いたら見出しにフォーカスし、閉じたら元の操作箇所に戻す。
- 基本はモーダルにせず、メニューとコア操作へ移動できる補助パネルとする。
- 小画面でも操作ボタンと本文が重ならない。

## 6. 発光コアの構成

Three.jsのWebGLRendererを基本とし、画像を回転するだけの実装にしません。

| レイヤー | 実装の方向 | 動き |
| --- | --- | --- |
| 中心 | 小さな高輝度の球 | 待機時に弱く脈動 |
| 球殻 | 低密度のワイヤーフレーム球・正二十面体 | ゆっくり回転 |
| リング | 太さの異なる複数の輪・部分円弧 | 軸と速度をずらして回転 |
| 粒子 | BufferGeometry + Points | 周回・揺らぎ |
| 連結線 | 間引いた線分 | 静的接続を基本に負荷を抑える |
| 発光 | EffectComposer + UnrealBloomPass等 | コアを中心に光をにじませる |

- 中心が白く潰れて巨大な円に見えないよう調整する。
- 奥側のリングは暗くし、手前との違いを作る。
- 粒子を増やす前に、輪郭・奥行き・回転の美しさを整える。
- 画面全体を激しく点滅させない。
- 音声連動はフレーム間で平滑化する。
- マウス位置でごく弱い視差を付けてもよい。操作必須にはしない。
- Blenderや有料3Dモデルを必須にしない。

### 品質設定の初期目安

| 項目 | 標準 | 軽量 |
| --- | --- | --- |
| 粒子数 | 約600〜1,200 | 約150〜350 |
| 描画ピクセル比の上限 | 1.5 | 1.0 |
| Bloom | 有効 | 解像度を下げる／無効 |
| 装飾線 | 控えめ | 少数のみ |

これは実測値ではなく開始時の調整値です。実機の描画時間を見て調整し、全端末で60fpsなどと保証しません。非表示タブでは描画を停止または抑制します。WebGL context loss時も本文閲覧を維持します。

## 7. 音声ファイル

音声はオーナーが録音した素材に差し替える方式です。初期実装時点では録音ファイルが未提供でも動くようにします。

| ファイル名の案 | セリフ | 必須度 |
| --- | --- | --- |
| welcome.mp3 | 何をする？ | 優先 |
| status.mp3 | ステータスを表示する | 優先 |
| research.mp3 | 研究内容を表示する | 優先 |
| publications.mp3 | 業績を表示する | 優先 |
| projects.mp3 | プロジェクトを表示する | 優先 |
| contact.mp3 | 連絡先を表示する | 優先 |
| help.mp3 | 選べる項目を表示する | 優先 |
| back.mp3 | ホームに戻る | 任意 |
| unknown.mp3 | もう一度話すか、項目を選んで | 任意 |
| ambiguous.mp3 | 項目を一つ選んで | 任意 |

### 録音の準備

- スマホのボイスメモ等で、静かな場所で録音する。
- 冒頭と末尾の長い無音を切る。
- 各ファイルの音量をそろえ、音割れを避ける。
- BGMは入れず、必要なら後で別音源として扱う。
- ブラウザで扱いやすいMP3を初期形式とする。
- 元の録音は手元に残し、Webには公開用ファイルを置く。
- public/audio/の音声は、公開後に訪問者が取得できる公開素材となる。

### 音声未提供時の動作

1. manifestで録音が設定されていれば、その音声を再生する。
2. 未設定または読込失敗なら、利用可能な日本語のSpeechSynthesisで代替する。
3. 代替音声が使えなければ字幕のみ表示する。
4. どの場合もパネルは開く。音声失敗でナビゲーションを止めない。

代替読み上げはオーナー本人の声ではありません。本人の声での完成確認は、実際の録音を配置した後に行います。存在しないMP3やダミーの無音ファイルを完成素材として扱わないでください。

## 8. 音声とコアの同期

録音をHTMLAudioElementで再生し、Web Audio APIで音量を取得します。

- AudioContextはユーザー操作を受けて作成／resumeする。
- 再利用する1つのaudio要素に対し、MediaElementAudioSourceNodeを1回だけ作る。
- 接続は「音源 → AnalyserNode → destination」とする。
- 同じaudio要素を再びcreateMediaElementSourceに渡さない。
- タイムドメインデータからRMS等で音量を算出し、平滑化して使う。
- 音量に応じて中心球のスケール・Bloom強度・リングの揺れを小さく変える。
- 再生終了・中断・失敗後は滑らかに待機値へ戻す。
- 音源は原則同じサイト内に置き、不要なCORS依存を作らない。
- ミュート時も字幕と画面切り替えは維持する。

SpeechSynthesisの出力は、このaudio要素のAnalyserNodeで直接解析できると仮定しないでください。代替読み上げ時はstart/endイベントに合わせた控えめな疑似脈動とし、実音量同期と区別します。

マイク音量に合わせた描画は任意です。初期版は音声認識の開始・終了に応じた待機アニメーションだけでも成立させ、装飾のためだけに別のマイクストリームを要求しないでください。

## 9. 音声認識

### 基本設定

- 実行時にwindow.SpeechRecognitionまたはwindow.webkitSpeechRecognitionを検出する。
- 未対応環境ではSPEAKを無効化し、クリック操作を案内する。
- langはja-JP。
- continuousはfalse。
- interimResultsは必要に応じて有効化し、操作実行は確定結果だけで行う。
- 音声認識はSPEAKの明示操作で開始する。
- 認識中にもう一度押した場合は停止する。
- 起動後に自動で認識を再開しない。
- 1回のセッションに最大約10秒の待機タイムアウトを設ける。
- 1回の発話につきコマンドを1回だけ実行する。
- 初期版の検証はChromeを優先し、他ブラウザも実機確認で対応状況を記録する。

ブラウザAPIによる認識は、ブラウザ提供の外部認識サービスを使う場合があります。「完全ローカル」「必ずオフラインで認識」「全ブラウザで動作」とは表記しません。サイト独自の課金API契約は不要ですが、サービスの可用性はブラウザや通信環境に依存します。

### エラー時の挙動

| 条件 | 表示・復帰 |
| --- | --- |
| 未対応 | 音声入力はこの環境では利用できません。項目を選んでください |
| マイク拒否・service-not-allowed | マイクを利用できません。クリックで操作できます |
| audio-capture | マイクが見つからないか、利用できません |
| no-speech／タイムアウト | 声を確認できませんでした。もう一度SPEAKを押してください |
| network | 音声認識に接続できません。クリックで操作できます |
| aborted | 通常の取消として静かに待機へ戻る |
| 不明なコマンド | 認識した文字と選べる項目を表示 |
| 複数候補 | 候補ボタンを表示し、勝手に選ばない |

許可ダイアログを繰り返し出さず、常に手動操作で復帰できるようにします。マイク拒否だけを理由にステータス閲覧を止めません。

## 10. 状態管理と競合防止

音声状態と表示中パネルを分けます。パネルが開いていることと、コアが話していることは同時に成立します。

```ts
type VoiceState = "idle" | "speaking" | "listening";
type PanelId =
  | "status"
  | "research"
  | "publications"
  | "projects"
  | "contact"
  | "help";

interface AppState {
  booted: boolean;
  voiceState: VoiceState;
  activePanel: PanelId | null;
  muted: boolean;
  recognitionSupported: boolean;
  transcript: string;
  notice: string | null;
}
```

### 遷移の原則

- コマンドを決めてから、パネルと返答音声を開始する。パネル表示は音声読込を待たせない。
- SPEAKを押したら、再生中の録音とSpeechSynthesisを止めてから認識を開始する。
- 発話結果が確定したら認識を終了し、そのセッションから二重実行されないようにする。
- 再生中に別メニューを押したら、古い音声を止めて新しい選択を優先する。
- 音声再生中もSPEAKとメニューボタンを使える。
- Escapeは認識・音声を中止し、開いているパネルを閉じる。
- 認識のendイベントでactivePanelを消さない。
- エラー処理後もidleに復帰し、操作可能な状態を保つ。
- ミュートした場合は再生を止め、speaking状態に取り残さない。
- tab非表示時は認識を中止し、音声再生を止める。再表示時に勝手に再開しない。
- セッションID／操作トークンを使い、古いonend・onerror・Promise完了が新しい操作を上書きしないようにする。
- 認識中の重複startを防ぎ、start失敗も捕捉する。

### 想定するサービス境界

- dispatchCommand(id, source)：音声／クリック／キーボードから共通で使う。
- navigateToPanel(id)：画面の変更とフォーカス処理。
- playVoice(key)：録音、代替読み上げ、字幕、取消。
- startListening()／cancelListening()：認識とタイムアウト管理。
- updateCore(state, level)：視覚表現。本文や認識処理を持たせない。

この分離により、選択肢の追加時にコア描画や認識サービスを変更せずに済むようにします。

## 11. メニューの設定データ

ラベル・別名・字幕・音声キーを一つの設定にまとめます。ファイルパスと字幕は音声manifest側で一元管理します。

```ts
type CommandId = PanelId | "back";

interface MenuItem {
  id: CommandId;
  label: string;
  aliases: string[];
  voiceKey: string;
}

export const menus: MenuItem[] = [
  {
    id: "status",
    label: "ステータス",
    aliases: ["ステータス", "プロフィール", "自己紹介"],
    voiceKey: "status"
  },
  {
    id: "research",
    label: "研究",
    aliases: ["研究", "研究内容"],
    voiceKey: "research"
  }
  // 他の項目も同じ形式で追加する
];
```

この例は抜粋です。実装では第4節の全項目を登録します。UIボタンと音声判定を別々の手書きリストにしないでください。

## 12. コンテンツ

### STATUS

名前、所属、研究分野、短い紹介、GitHub等の公開リンクを表示します。ゲーム風の装飾は使っても、根拠のない能力値・レベル・実績を捏造しません。

### RESEARCH

テーマ名、何を解決したいか、方法の概要、関連リンクを表示します。非公開の研究成果や未確認の数値を掲載しません。

### PUBLICATIONS

題名、著者、会議・年、論文や発表資料へのリンクを表示します。採択済み・投稿中などの状態は、確認できた情報だけ記載します。

### PROJECTS

名称、短い説明、使用技術、コード／デモへのリンクを表示します。未確認のURLや架空の制作物を入れません。

### CONTACT

オーナーが公開を希望する連絡手段だけを表示します。メール送信サーバーは作らず、メールリンク等を使用します。

### データの扱い

- 名前と既知のホームページURL以外は、提供資料または既存サイトの現在の情報を確認して反映する。
- 不明項目は空欄や「準備中」で表し、推測で補完しない。
- 空の業績・プロジェクト一覧にも整った空状態を用意する。
- 情報はsrc/content/へ集約し、描画コードから編集を分離する。
- 外部リンクの表示名を明確にし、開くために音声認識を必須にしない。
- ステータス風に表示するSYSTEM READY等はUIの状態。CPU・GPU使用率などを取得していないのに実測風の値を表示しない。
- 装飾的なデータ流を使うならSIMULATION等とし、個人情報や本物のシステムログに見せない。

## 16. GitHub Pagesのパス設定

### オーナーサイト

リポジトリがmao-takubo.github.ioで、公開URLがhttps://mao-takubo.github.io/の場合はbaseを/にします。

### プロジェクトサイト

別リポジトリmao-coreで、公開URLがhttps://mao-takubo.github.io/mao-core/の場合はbaseを/mao-core/にします。

### 設定例

```ts
// vite.config.ts
import { defineConfig } from "vite";

export default defineConfig({
  base: process.env.PAGES_BASE_PATH || "/"
});
```

PAGES_BASE_PATHは公開パスの設定であり、秘密値ではありません。上記をTypeScriptで検査する場合は、Vite設定用のNode型を含めます。

public配下の音声は、baseを考慮して読み込みます。

```ts
// 例：pathはmanifestに記録された "audio/status.mp3"
const audioUrl = new URL(
  import.meta.env.BASE_URL + path,
  window.location.origin
).href;
```

pathは先頭/を付けない相対パスとし、manifestも同じbase配下から読み込みます。/audio/status.mp3のようなルート固定を全体に散らさないでください。manifestはHTTPステータスも確認し、JSONの形式を検証します。

画面切り替えは同じページ内の状態変更を基本とします。/research等のHistory APIルートを無設定で追加して、直接アクセス時に404になる構成にしません。URL共有が必要ならハッシュ方式等を明示して採用します。

## 17. GitHub Actionsによる公開

GitHubのSettings → Pages → Build and deploymentでSourceをGitHub Actionsに設定します。

以下はmainブランチを使う場合の雛形です。既存リポジトリのブランチ・Pages設定・Actionsと競合しないよう実装時に合わせます。アクションのメジャー番号は導入時の公式推奨も確認し、必要なら更新します。

```yaml
name: Deploy GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v7

      - name: Set up Node.js
        uses: actions/setup-node@v7
        with:
          node-version-file: .nvmrc
          cache: npm

      - name: Install
        run: npm ci

      - name: Typecheck
        run: npm run typecheck

      - name: Build
        run: npm run build
        env:
          PAGES_BASE_PATH: /

      - name: Configure Pages
        uses: actions/configure-pages@v6

      - name: Upload artifact
        uses: actions/upload-pages-artifact@v5
        with:
          path: dist

  deploy:
    needs: build
    runs-on: ubuntu-latest
    permissions:
      pages: write
      id-token: write
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - name: Deploy
        id: deployment
        uses: actions/deploy-pages@v5
```

プロジェクトサイトではPAGES_BASE_PATHを/mao-core/などへ変更します。既存のCNAME、カスタムドメイン、公開中ファイルを不用意に消さないでください。アプリを導入するだけで既存サイトを無断公開・上書きせず、まずローカルで変更を確認できる形にします。

## 18. モバイル・アクセシビリティ・代替表示

- 幅360px程度から横スクロールなしで使える。
- 操作領域は目安44px以上とし、SPEAKを押しやすくする。
- Tabでメニュー・SPEAK・ミュート・閉じるへ移動できる。
- ボタンはbutton、リンクはaを使い、Canvas上の座標だけで操作させない。
- マイク入力中は文字と見た目の両方で明示する。
- 字幕と認識結果は別の領域にし、混同しない。
- aria-liveでは「聞いています」「ステータスを表示しました」等を通知し、毎フレーム値を読み上げない。
- prefers-reduced-motionでは回転・視差・粒子の動きを抑え、パネル表示を簡素化する。
- ミュート設定は必要ならlocalStorageに保存してよい。認識履歴は保存しない。
- 音声入力未対応・許可拒否・ネットワーク不調でも、全メニューが使える。
- WebGLが使えない場合はCSS等の静的なコアとDOMパネルを表示する。
- JavaScript無効時は最低限、名前・説明・確認済みリンクをnoscript等で表示する。
- 本文を開くために長い起動アニメーションを必須にしない。
- 外部リンクの新規タブには適切なrelを付ける。
- 入力文字はtextContent等で表示し、未加工のinnerHTMLへ流さない。

マイクを使う直前に、「音声認識はブラウザのサービスへ送信される場合があります。クリックでも操作できます」と短く案内します。初期版ではサイト独自のアクセス解析・認識ログ送信を追加しません。

### 基本動作

- [ ] 初回アクセスでオレンジ色の立体コアが表示される。
- [ ] 初回アクセスだけでマイク入力や音声再生が始まらない。
- [ ] コア／起動ボタンで「何をする？」と案内し、字幕が出る。

- [ ] 複数候補・不明語・否定表現で誤った画面を勝手に開かない。

- [ ] 録音がある場合は本人の声が再生される。
- [ ] 録音の音量とコアの動きが同期する。
- [ ] 音声未提供・404・形式不正でも画面を開ける。

- [ ] コア発話中にSPEAKを押すと、発話が止まって入力へ移る。
- [ ] SPEAK連打で重複startやコマンド二重実行が起きない。
- [ ] 別メニューへの切り替えで、音声が重ならない。
- [ ] ミュート・Escape・タブ非表示で適切に中断できる。
- [ ] 認識終了イベントが開いたパネルや次の操作を上書きしない。

### 失敗時・表示

- [ ] マイク拒否・未接続・無言・認識未対応を再現して、手動操作へ復帰できる。
- [ ] 音声再生ブロック時に字幕・再生ボタンが使える。
- [ ] WebGL無効時にもプロフィール等へ到達できる。
- [ ] 長文・空リスト・未入力プロフィールでも表示が崩れない。
- [ ] 小画面・横向き・拡大表示でボタンが隠れない。
- [ ] キーボードとreduced-motion設定で使える。
- [ ] 通常操作でコンソールに未処理例外がない。

### ビルド・公開

- [ ] npm ci、npm run typecheck、npm run buildが成功する。
- [ ] npm run previewで本番成果物を確認する。
- [ ] /とプロジェクト用サブパスのビルドで、音声・manifest・JS・CSSが読み込める。
- [ ] GitHub PagesのHTTPS公開先で実際のマイク操作を確認する。

コマンド判定・状態の取消・セッション競合は、必要最小限のユニットテストに向いています。自動ブラウザテストで音声認識をモックした場合も、実機のマイク検証を行ったことにはしません。モックの確認と実音声の確認を分けて報告してください。

- 旧サイト（Hugo + PaperMod + 3Dチェス）は Git タグ `chess-hugo-v1` に保存済みです。戻すには `git switch --detach chess-hugo-v1`、または `git switch main`（main はチェス版のまま）を使います。
- 本実装はブランチ `mao-core` にあります。`main` へマージして push すると GitHub Pages に公開されます（`.github/workflows/deploy.yml`）。公開前に `npm run preview` で確認してください。
- Pages の Source は **GitHub Actions** のままで使えます。

## コマンド

```bash
npm ci
npm run dev        # 開発サーバー
npm test           # コマンド判定・状態遷移のユニットテスト
npm run typecheck
npm run build      # dist/ を生成
npm run preview    # 本番ビルドの確認
```

Node.js は 22.12 以上（`.nvmrc` は 22）。依存は three 0.170.0 / vite 8 / typescript 7 / vitest 4。

## 録音の差し替え方

1. `public/audio/` に `welcome.mp3`、`status.mp3` などを置く。
2. `public/audio/manifest.json` の該当項目の `path` を `null` から `"audio/status.mp3"` のように変える（先頭に `/` は付けない）。
3. 再生できない・未設定のときは、日本語の読み上げ → 字幕のみ、の順で自動的に代替されます。

現在は、機械音声パック（Open JTalk / HTS Voice "Mei"、CC BY 3.0。本人の声ではありません）の10個のMP3を `public/audio/` に配置済みです。クレジットはヘルプパネルに表示しています。ライセンス原文は `public/audio/LICENSE_mei_normal.htsvoice`。本人の録音に差し替える場合は、同名ファイルで上書きし、ヘルプパネルのクレジットを削除してください。
